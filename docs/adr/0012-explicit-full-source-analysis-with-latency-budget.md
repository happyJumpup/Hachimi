# 0012：显式触发的整段视频分析与延迟预算

状态：已接受（2026-07-21）

> 冲突部分先后由 [ADR-0013](0013-local-video-import-and-recoverable-analysis.md) 与 [ADR-0031](0031-deep-content-provider-and-sequential-visual-fallback.md) 取代。联系表、11.5 秒证据预算、局部触发窗口和 SSE 断开即取消均为历史实现；显式触发、完整覆盖和临时材料边界继续有效。

## 背景

按播放时间点截取局部窗口，会把用户的任务错误地缩成“猜当前动作”。用户真正需要的是：明确选择一个受控来源视频后，由系统一次找出整段视频里可训练的动作，再由用户校正和选择。整段分析也不能在打开页面、播放或拖动进度条时自动发生，否则会浪费云额度并产生不可预期等待。

旧链路上传视频窗口到 Ark 预处理，单条约 55 秒视频可能超过 180 秒；改用整段音频与均匀视觉联系表后，仍需要把模型抖动限制在可接受的交互时长内。

## 决策

1. 用户必须点击“分析视频动作”才创建 Analysis Run。打开页面、播放、暂停、拖动进度条和切换来源都不会自动分析。
2. 新客户端只提交 `source_id`。`trigger_seconds` 作为可选、已弃用的兼容字段继续被后端接受，但不影响分析范围、候选排序或模型提示。
3. 竞赛版完整覆盖后端登记且时长不超过 60 秒的受控视频。清单声明或实际媒体时长超过 60 秒时，来源目录直接失败关闭，不向前端列出后再等用户点击失败；不以多分钟稀疏抽样冒充完整分析。更长视频需要后续的分块并行设计和新 ADR。
4. 后端并行生成 16 kHz 单声道 PCM 音频和整段视觉联系表。音频就绪后立即启动 ASR，联系表继续生成，视觉分支自行等待，从而让媒体处理与云分析重叠。
5. 视觉联系表约每 3.5 秒取一帧，最多 18 帧，按时间顺序排列；返回的动作时间仍是来源视频的绝对秒数。联系表是瞬时材料，不生成长期裁剪视频。
6. 豆包流式语音识别模型 2.0 使用现有 `bigmodel_nostream` WebSocket 权益，以 4 秒 PCM 包不按实时速度发送，只消费最终结果和时间戳。Ark 语音理解与视觉定位默认使用 `doubao-seed-2-0-mini-260428`，并关闭思考模式；模型 ID 均可由环境变量替换。
7. ASR 与视觉分支从音频就绪起共享 11.5 秒证据决策预算：到点后停止等待新证据并取消未完成分支。所有 Provider 任务必须在媒体上下文退出前完成回收；清理耗时同样计入端到端 smoke。一个分支超预算、另一个已有可靠证据时返回真实部分成功和对应警告；两个分支都无可用证据时明确失败。180 秒仍只是进程级安全上限，不是交互目标。
8. 本地真实 smoke 把不超过 15 秒/视频分钟作为发布门禁，并继续校验动作语义、人工时间段交集、无重量字段、分支与警告一致性以及临时材料清理。快于 5 秒/视频分钟不视为失败；5–15 秒/视频分钟是体验预期，不是对公网网络的 SLA。
9. 用户取消、切换视频、离开页面或 SSE 断开时，父任务和两个 Provider 子任务一起取消；迟到结果不得回填。音频、联系表、转录和模型响应只在当次运行内存或独立临时目录中存在。

## 结果

- 产品从“当前时间附近找一个动作”变为“显式触发后分析整段受控视频中的动作”。
- 语音提供动作名称与明确参数，视觉提供全时间线的定位依据；两者仍可独立部分成功，用户始终负责最终确认。
- 首版对视频时长作出真实限制，避免把多分钟视频的少量截图宣传为完整分析。
- `calculate_analysis_window` 与旧视频窗口接口暂留给内部兼容和历史测试，主运行路径不再调用。
- 本决策取代 ADR-0009 中“局部分析窗口、200 ms 实时节奏包”的运行细节，并取代早期纵切片文档中的局部扩窗语义；ADR-0006、0008 的瞬时材料和可取消边界继续有效。

## 验证基线

2026-07-21 在一条 54.87 秒受控旧视频上连续三次真实 Ark + ASR smoke 均通过，观测为 10.96、12.90 和 13.41 秒/视频分钟。前两次语音与视觉均完成；第三次语音完成、视觉超预算后按部分成功返回警告。三次都满足动作语义与 41–51 秒标注相交、无重量字段和清理门禁。该结果只证明当前单来源本地基线，不替代最终 2–3 条授权视频和目标服务器验收。
