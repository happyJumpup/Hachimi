# ADR-0045：公开真实分析保留单并发但取消会话／IP 冷却

状态：已接受（2026-07-23）

取代：ADR-0043 的会话／IP 600 秒频控和冷却后恢复门槛。ADR-0043 的公开单并发、评委并发为零、无队列、容量原因头和旧 Cookie 不扩容仍然有效。

## 背景

设备演示链接不对游客主动公开，现场需要在团队自己的设备上连续演示真实分析。ADR-0043 的会话与 IP 双重十分钟冷却能限制链接泄漏后的串行调用，却也会让同一设备、同一网络下的下一次演示必须等待，并使最短受控来源和 295 秒上传门槛无法在发布窗口内连续验收。

真实视频分析仍由单实例、单 worker 和一个公开租约保护。团队已明确接受不设置会话或 IP 次数额度，成本保护改由不公开链接、全局单并发、300 元总预算观察和紧急关闭入口承担。

## 决策

- 生产保持 `PUBLIC_ANALYSIS_CONCURRENCY=1`、`JUDGE_ANALYSIS_CONCURRENCY=0`。受控来源与本地上传共享同一个非排队公开分析槽。
- 不再按匿名会话或对端 IP 记录成功尝试历史，也不设置分析完成后的冷却窗口。运行到达终态、租约释放且临时媒体／FFmpeg 清理完成后，同一会话可以立即创建下一条分析。
- 当生产评委池容量为零而公开池已启用时，仍在有效期内的旧评委 Cookie 自动降级为普通公开会话并共享同一个公开槽；它既不要求现场清理 Cookie，也不能增加第二条并发容量。
- 第一条运行占用槽时，并发第二条创建必须立即返回 `429 + Retry-After + X-TrainPal-Admission-Reason: capacity`。兼容保留的评委 Cookie 或体验码不能增加容量。
- 同一会话已有活动运行时仍可返回 `session_active`；Provider 或 readiness 不可用仍失败关闭。上述运行态不是完成后的次数频控。
- `GET /api/v1/access/session` 只反映 readiness、当前会话活动运行和全局槽是否可用，不再根据会话／IP 历史返回冷却剩余时间。
- GYMTI Ark／豆包继续使用独立的非排队三并发门，不占用视频分析槽，也不受视频分析运行历史影响。

## 发布门槛

公开 Canary 必须在同一个 Cookie 会话中证明：

1. 首条真实分析创建返回 `202`，并通过 SSE 到达符合覆盖合同的终态。
2. 首条运行占用槽时，并发第二条创建返回带 `capacity` 原因的 `429`。
3. 首条运行终态后，`/api/v1/runtime-cleanup` 证明没有媒体残留或 FFmpeg 子进程。
4. 同一会话立即再次创建同类分析并获得 `202`，不等待冷却。
5. 第二条运行立即取消并到达 `cancelled`，随后再次证明运行时清理完成。

Canary 回执只记录状态、计数、覆盖聚合和清理证据，不记录会话 ID、IP、来源身份、媒体路径、分析候选或内容。

## 后果

现场连续演示不再被十分钟等待阻断，发布验收也不需要为冷却窗口暂停。代价是拿到链接的人可以在前一条结束后串行消耗真实 Provider；单并发只限制同时调用，不限制累计次数。若链接泄漏、费用接近 300 元或供应商异常，操作方必须立即关闭公网或停止新的模型调用，而不是依赖隐含的会话／IP 配额。

ADR-0043 继续保留为历史决策记录。
