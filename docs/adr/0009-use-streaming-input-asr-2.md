# 0009：使用豆包流式语音识别模型 2.0

## 决策

首个动作分析纵切片使用豆包流式语音识别模型 2.0 的 WebSocket
`bigmodel_nostream` 模式。后端将局部分析窗口转换为 16 kHz、16-bit、单声道
PCM，以 200 ms 音频包发送，并仅消费末包后的最终识别结果及词级时间戳。

默认资源 ID 为小时版 `volc.seedasr.sauc.duration`；并发版可通过
`VOLC_ASR_RESOURCE_ID=volc.seedasr.sauc.concurrent` 替换，不在代码中猜测用户
实际购买的计费方式。

## 原因

产品分析的是已经截取好的局部音频，不需要向界面展示实时听写中间结果；但团队
现有权益属于流式语音识别模型 2.0，而不是录音文件极速版。流式输入、末包返回最终
结果的模式既复用现有权益，也保持了动作分析 Agent 的一次性、可取消语义。

## 影响

- ASR Provider 使用 WebSocket 二进制协议，不再 Base64 提交整段 WAV。
- 取消分析会关闭连接；网络、握手限流和服务端可重试错误会重连并重传当前临时片段，
  最多重试两次。
- API Key 只进入后端握手 Header，不进入请求正文、日志或前端构建产物。
- 若购买的是并发版，部署时必须显式覆盖资源 ID；应用协议和产品交互无需变化。
