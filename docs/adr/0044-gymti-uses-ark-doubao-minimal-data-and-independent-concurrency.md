# ADR-0044：GYMTI 使用 Ark／豆包最小数据与独立三并发降级

状态：已接受（2026-07-23）

取代：ADR-0034 中“竞赛生产默认关闭、匿名固定本地降级、依赖评委会话与分析租约”的模型准入部分，以及 ADR-0041 中双重默认关闭和评委门禁部分。两份旧 ADR 的确定性规则、最小输入、输出校验、日志白名单和供应商留存边界继续有效。

## 背景

GYMTI 的 LLM 只负责从合法候选中选择下一题和叙述已经由本地合同确定的结果。它不需要读取展示文案、身体档案、用户身份、训练历史或自由文本画像，也不应与耗时更长的媒体分析争用同一租约。竞赛版希望保留公开问卷的路径变化感，同时保证模型拥塞、失败或供应商配置不满足隐私边界时，问卷仍能立即完成。

## 决策

- 竞赛生产的 GYMTI 模型提供方固定为现有 Ark `/api/v3` 兼容端点与 `doubao-seed-2-0-mini-260428`；视频分析的 `ARK_MODEL_ID` 继续独立配置，不能让它覆盖 GYMTI 模型。不得因为参考原型使用 DeepSeek，就把 DeepSeek 默认值、密钥别名或原型请求体当作生产路线。更换提供方或模型需要 Issue #5 的隐私、质量、成本和降级证据及新的 ADR。
- 选题请求只发送合同／问卷／评分版本、已验证的稳定题目与选项 ID、合法候选题目 ID，以及服务端从共享合同派生的语义标签、计分态势、排除项、缺失信号和候选探查目标。不得发送展示题干、选项文案、训练档案、身份信息、训练历史、已确认风格或自由用户画像。
- 结果叙事只发送版本、已经成立的主要／可选次要类型 ID、推荐风格 ID 和最多三个正向原因码。逐题回答、分数、负向信号、安全排除、档案和其他用户上下文不发送给模型。
- GYMTI 模型使用独立的、进程内、非排队三并发门，配置为 `GYMTI_LLM_CONCURRENCY=3`。它不读取或消耗公开分析的单并发槽、运行状态或评委访问级别；公开分析已由 [ADR-0045](0045-public-analysis-keeps-one-slot-without-session-or-ip-cooldown.md) 取消完成后的会话／IP 冷却。
- 前三条同时进行的合法模型请求可以调用 Ark／豆包；第四条及之后的并发请求不等待、不报错，立即使用版本化本地选题或模板叙事并正常返回。超时、网络错误、非法输出、模型不可用或有限重试耗尽同样降级。
- 目标生产配置为显式启用模型并确认供应商训练／内容留存设置满足 ADR-0041。若发布人不能在目标账号中确认该边界，模型客户端不得构造，本地确定性路径继续可用；这不能被表述为 Ark／豆包线上验证通过。
- API 和应用日志继续只允许请求 ID、版本、模型名、耗时、成功／重试／降级状态、所选下一题 ID 和错误类别，不记录请求正文、选项、得分、原因码、提示词、模型原文或结果叙事。

## 发布门槛

新候选必须证明：Ark／豆包实际请求使用上述白名单载荷；三个并发模型请求可被接纳；第四个请求在不等待模型的情况下返回本地降级；模型错误与非法输出不改变正式计分或中断问卷；日志和回执不包含问卷内容；本地模板在未配置或未确认留存时仍完整可用。仓库测试或原型 DeepSeek 调用不能替代目标 CloudBase 候选的真实验证。

## 后果

公开用户可以获得有变化的选题和叙事，但模型只参与受限的表现层决策，且拥塞时体验连续。GYMTI 的三并发不会挤占唯一真实视频分析槽。由于 Ark／豆包的目标生产配置和线上 smoke 仍需在候选发布时核对，本文记录的是已接受运行合同，不是已经上线成功的声明。
