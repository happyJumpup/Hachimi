# ADR-0030：竞赛版使用五分钟分块分析与签名源码构建 FFmpeg

状态：已接受（2026-07-23）

## 背景

竞赛版需要让评委上传自己有权使用的完整视频，同时诚实表达 Provider 对完整来源的实际覆盖。既有 60 秒单次视觉分析不能直接外推到多分钟视频；CloudBase Run 又必须在 180 秒应用上限、单实例和 300 元总预算内运行。生产镜像还需要一份可复核、许可证边界明确且不会与 wheel 内置二进制混用的 FFmpeg。

## 决策

- 对外能力上限固定为完整源文件不超过 300 秒、上传体积不超过 256 MiB。7 分钟或 19 分钟原片必须先在应用外裁成不超过 5 分钟的新源文件，不能用内部时间范围冒充首次完整分析。
- 当前比赛基线继续使用已经接入的火山 ASR、Ark Seed 与确定性候选融合。一次运行只抽取一次完整分析范围的音频并执行一次 ASR；视觉按 60 秒窗口、10 秒重叠顺序处理，每个窗口以连续 MP4 作为 Provider 输入，不用少量截图或拼图代替整块检查。内部视觉块转为不高于 1280 像素宽、15 fps、4 Mbps 的 LGPL MPEG-4，单块必须不超过 45,000,000 bytes。
- Ark Responses API 以 `input_video.video_url=data:video/mp4;base64,...` 和 `fps=1` 接收视觉块，并显式使用 `ARK_VISUAL_MODEL_ID`。比赛基线不调用 Files API，因此取消或超时不会留下无法取得 ID 的方舟托管文件；45 MB 内部上限为官方 50 MB 文件与 64 MB 请求体限制留出编码和 Schema 余量，超过时该块以 `media_error` 形成覆盖缺口，而不是改走不可审计的上传路径。该内部上限不改变 256 MiB 的用户源文件上传上限。
- 语音理解和每个视觉块都只允许模型返回从 0 开始的片段局部时间；编排层在融合前只加回视觉分块相对于本次分析范围的偏移，输出仍保持为分析范围局部时间。Run Manager 先按分析范围时长验证候选、证据和缺口，再且仅再加一次 `analysis_start_seconds`，形成公开的源视频绝对时间。模型不得自行换算或猜测源视频绝对时间。因此首次全源分析、覆盖缺口和范围重试都只向外返回源视频绝对时间。
- 已可靠完成的视觉窗口不会因后续窗口失败而丢弃。失败窗口扣除与成功窗口重叠后形成 `coverage_gaps`：有可靠候选时返回 `partial`，没有足够可靠候选时返回 `insufficient`，全部窗口可靠检查完成时返回 `complete`。
- 管线在 Run Manager 的外层 180 秒超时前预留 10 秒终态与清理余量；语音和视觉共享 170 秒证据截止时间。剩余预算不足以完成下一块的完整 20 秒预算时，不再启动该块，并把尚未可靠检查的窗口登记为 `timeout` 缺口；语音也只能使用截止时间内的剩余预算。ASR 失败且可靠视觉检查也没有产生动作证据时，整次结果为 `insufficient`，不能表述为可靠的“无动作”。
- 组数、次数、动作时长和休息只能来自带时间的语音或其他可定位证据；公开合同没有重量字段。`segment_role` 只允许作为 Provider 内部信号影响“需确认”，不进入公开或持久化的 `AnalysisCandidate`。
- `AnalysisPipeline` 是可替换的内容理解策略边界。研究方案只有同时通过证据真实性、结构校验、临时材料与远端文件清理、无虚构参数和可复现实测门槛后才可成为候选；多个合格方案按宏平均 F1 选择，平分时选择成本与时延更低的 Mini。没有合格方案时继续使用本 ADR 的当前 Provider 基线。
- 生产允许只有本地上传入口。`LOCAL_UPLOAD_ENABLED=true` 且未配置任何受控来源字段时，`/sources` 可以为空，`/ready` 不要求 manifest、媒体根目录或公开媒体地址；如果只配置受控来源三项中的一部分，则继续失败关闭。
- 竞赛生产 `/ready` 还必须核对实际运行档为 300 秒、256 MiB、170 秒证据截止、60／10 秒分块、20 秒分块上限、180 秒运行上限、评委并发 3、匿名并发 0 与空可信代理列表；仓库计划文件通过不能替代运行时检查。
- `TRUSTED_PROXY_CIDRS` 在未获得 CloudBase 可信网段事实前保持为空。应用只使用直连对端地址并忽略任意转发头；比赛额度由强评委码、匿名并发为零和全局评委并发上限保护。
- 生产镜像从 FFmpeg 8.1.2 官方签名源码构建唯一一份共享库版本。构建必须核对官方签名主密钥指纹，保持 LGPL-only，不启用 GPL 或 nonfree，并生成包含版本、源码地址、签名指纹、配置行及其 SHA-256、二进制 SHA-256 的收据。`/ready` 和镜像审计都必须校验该收据并拒绝第二份 FFmpeg。

## 发布约束

后端基建版本 A 先保持 OA 私有访问，完成容器、FFmpeg、`/ready`、SSE 和真实短视频验证；前端提交后生成同一 OpenAPI 契约并发布版本 B。只有私有门槛和公网 Canary 全部通过后才能向评委提供链接。版本 A 与兼容环境配置保留为回滚点，并实际演练 B→A→B。匿名访客可以浏览页面，但 `PUBLIC_ANALYSIS_CONCURRENCY=0`，只有持评委码会话可以消耗模型额度。

评委窗口内最小实例数为 1，其余时段恢复为 0；累计费用接近 300 元前停止新增模型调用。最迟在 `2026-07-25T00:00:00+08:00` 关闭公共入口并缩容。

## 后果

五分钟表示系统真实检查完整上传文件的技术上限，不是准确率或延迟 SLA。重叠窗口会增加视觉调用次数和成本，单并发顺序处理会牺牲速度换取内存、预算和缺口定位的可控性。用户确认、编辑或删除结果是正常产品流程，但不能把系统失败伪装成人工补全。
