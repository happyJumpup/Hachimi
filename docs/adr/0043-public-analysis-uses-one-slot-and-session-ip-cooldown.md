# ADR-0043：公开真实分析使用单并发与会话／IP 双重频控

状态：已接受（2026-07-23）

取代：ADR-0011 中两个准入池与三路评委容量，以及 ADR-0029 与 ADR-0030 中“匿名分析并发为 0、真实分析必须使用评委码、评委分析并发为 3”的访问与容量部分。

## 背景

竞赛链接需要让评委和普通访客直接体验真实分析。强制先输入评委码会增加现场摩擦，而单进程、单实例的 Analysis Run 与真实 Provider 预算又不适合开放排队或多路匿名并发。仅按浏览器会话限制容易通过清 Cookie 绕过，仅按 IP 限制又会让共享网络中的访客争用同一身份，因此需要同时使用两个维度并把容量边界保持得足够小。

## 决策

- 竞赛生产设置 `PUBLIC_ANALYSIS_CONCURRENCY=1`、`JUDGE_ANALYSIS_CONCURRENCY=0`。公开会话可以直接创建受控来源或本地上传的真实分析，不要求先取得评委码。
- 全部公开会话共享一个非排队的真实分析槽。槽已占用时立即返回 `429 + Retry-After`，不创建运行、不缓存待处理请求，也不通过增加 worker 或实例扩容。
- 每个成功取得分析租约的公开请求，同时在匿名会话 ID 和服务端认可的客户端 IP 上记录一次尝试。任一维度在滚动 600 秒窗口内已有一次尝试，后续创建立即返回 `429 + Retry-After`；更换 Cookie 不能绕过 IP 冷却，共享 IP 下也不能用另一个会话绕过。
- 只有通过输入校验并成功取得租约的 Provider-backed 创建计入尝试。页面浏览、能力／来源读取、格式错误、媒体超限、未就绪和容量拒绝不消耗次数。
- `GET /api/v1/access/session` 使用同一会话／IP 规则返回 `can_analyze` 和剩余等待时间；它是状态提示，不预留容量。
- 在 `TRUSTED_PROXY_CIDRS` 为空时只使用直连对端地址，忽略任意转发头。只有获得并实测 CloudBase 的窄可信代理网段后，才能按既有校验规则使用转发地址。
- 评委体验码接口可以为兼容或运维验证保留，但它不再是公开真实分析的必要条件，也不得增加另一组付费分析并发。

## 发布门槛

新候选只有同时通过以下门槛才可公开：一个公开会话创建返回 `202`；运行结束后同一会话和同一 IP 的新会话在 600 秒内均收到带剩余时间的 `429`；并发的第二个请求在首个运行占用槽时收到 `429`；窗口结束后重新获得资格；SSE、终态清理和单实例状态无串流或泄漏。旧 `trainpal-demo-009` 的三路评委并发记录只作为历史容量证据，不能证明本决策已在线上生效。

## 后果

公开链接无需分发体验码，现场路径更短；代价是同一公网 IP 下的访客共享十分钟频控，且任意时刻只有一条真实分析。快速体验、已有方案和 GYMTI 本地降级仍可在分析槽不可用时使用。该限制是 300 元总预算和单进程一致性下的竞赛边界，不是长期生产容量承诺。
