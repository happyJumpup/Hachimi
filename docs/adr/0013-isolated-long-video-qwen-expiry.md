# 0013：长视频本地基准中的 Qwen 临时对象自动失效例外

状态：已接受（2026-07-22）

## 背景

ADR-0006 要求分析材料在成功、失败和取消后清理。7/19 分钟路线验证的 Qwen3-VL 原生上传接口会创建 DashScope 临时 OSS 对象；该受控上传链路向调用方提供 48 小时自动失效生命周期，但不提供同一链路可验证的逐对象删除接口。

把这个限制悄悄当成“已删除”会破坏实验的清理门禁；把它扩展到产品媒体又会扩大用户数据边界。因此需要将它限制为一次明确、可审计的本地研究例外。

## 决策

1. 本决策只适用于 Git 忽略目录下、团队已授权的 7/19 分钟长视频本地 A/B 基准；不适用于产品 API、受控来源清单、COS/CDN、用户媒体或未来部署。
2. Qwen 临时 OSS 对象使用提供方声明的 48 小时自动失效策略。运行只记录失效时间、提供方、模型、媒体类别和清理结果；对象键、URL、原始媒体、转录、提示词和响应一律不进入提交内容或脱敏报告。
3. 运行器必须在取得每次 Qwen 上传对应的 48 小时失效边界后、启动 multipart
   传输前，将失效时间原子写入 Git 忽略的脱敏 lifecycle journal；落盘失败时禁止
   启动传输。缺失、过期异常、上传结果不明确、取消或生命周期校验失败应记为到期
   留痕或清理失败；这样的 arm-run 不得成为有效质量或成本结论的一部分。
4. lifecycle journal 是每次 Qwen 上传的必需运行依赖；缺失时必须在传输边界前失败。
   并发校准和正式实验还必须在媒体预处理前检查该依赖。进程内或空操作 sink 只允许
   用于单元测试，不得满足真实运行门禁。
5. 最后一个失效时间经过 48 小时边界及 5 分钟安全余量后，运行
   `audit-expiry` 生成绑定 manifest 与 lifecycle journal SHA-256 的 Git 忽略脱敏
   receipt。`provider_ttl_elapsed` 只表示提供方声明的 TTL 已经过时，不表示逐对象已
   验证删除；缺失 journal、未到期或任何失败记录继续保持阻塞。评分报告只能在 receipt
   与当前 journal 哈希一致时标记为 `provider_ttl_elapsed_research_only`，仍不得据此直接
   升级生产 Provider。
6. Seed 联系表使用内嵌图像，不创建 Ark 文件。若后续路线改为创建 Ark 临时文件，仍必须按 ADR-0006 即时删除并验证，不可援引本例外。

## 结果

- 长视频实验不会把“自动失效”伪装成即时删除。
- 原始材料仍不进入仓库、产品数据面或公开部署。
- 生产接入必须在目标服务器重新评估 Provider 删除能力和用户媒体边界，不能直接继承本研究例外。
