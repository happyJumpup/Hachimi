# 0011：竞赛部署采用同源单实例

## 状态

已接受，2026-07-21。

## 背景

动作分析请求、SSE 事件、取消句柄和终态 TTL 当前都存在 FastAPI 进程内存中。竞赛现场需要稳定服务三名评委和约 10–50 名访客，但访客的大部分训练体验在浏览器本地运行，不需要把三天工程扩展成分布式任务系统。

## 决策

- 竞赛版由 Caddy 提供唯一同源 HTTPS 入口，后接一个 FastAPI 实例和一个 Uvicorn worker；Vue SPA 随同 `app` 镜像提供。
- 浏览器播放团队授权的 COS/CDN 媒体，后端只分析部署时同步并通过清单、SHA-256 校验的本地只读副本。
- 评委和公共分析使用两个内存准入池；容量不足立即返回 429，不创建队列、不启动后台任务、不使用假 Provider 回退。
- SSE 必须透传且禁止代理缓冲。断线取消当前请求，应用重启使全部进行中分析失效；用户可以重新发起新请求。
- 密钥和体验码只通过服务器环境文件注入。生产 ready 必须验证真实 Provider 配置、来源媒体、临时目录和访问配置，测试 Provider 不得启动。
- 50 人容量目标覆盖静态页面、快速体验和本地训练；真实模型只验证受控的三路评委并发。

## 影响

- 竞赛版不能增加 Uvicorn worker、应用副本或随机负载均衡，否则同一 `run_id` 的 SSE、取消和限流会失去一致性。
- 单实例重启会中断分析，但不会丢失浏览器 IndexedDB 中的方案和训练；现场以重试和上一镜像 SHA 回滚恢复。
- 若以后需要多实例，必须先引入共享运行注册表、跨实例取消和容量协调，或证明端到端会话粘滞，并以新 ADR 取代本决策。
- 该架构不是公开规模化上线承诺；它是三天竞赛交付中最小且可验证的正确性边界。
