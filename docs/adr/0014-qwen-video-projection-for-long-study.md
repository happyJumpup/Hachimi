# 0014：长视频 Qwen 臂采用固定低负载视频投影

状态：已接受（2026-07-22）

## 背景

长视频 A/B 研究的 Qwen3-VL 臂原先把完整分块以接近源文件的 MPEG-4 编码上传到
DashScope 临时 OSS。真实 8 秒片段在本机显式 SOCKS5h 出口上于 multipart 阶段超时，
而 Qwen 的配置、最小调用和合成媒体门禁均已通过。这发生在模型推理和本地 JSON
校验之前，不能据此判断 Qwen 的识别能力。

同一真实画面经低帧率 H.264 投影后，8 秒和 60 秒均完成“上传、原生 Qwen 推理、
一次本地 Pydantic 校验、TTL 留痕”链路。该证据仅说明本机传输兼容性恢复，不构成
质量或生产延迟结论。

## 决策

1. 仅在隔离的 7/19 分钟研究中，Qwen 视频臂固定使用
   `qwen-h264-short-edge-160-2fps-crf35-v3`：保留完整源时钟窗口，移除音轨、使最短边
   至少为 160 像素、采样为 2 FPS，并使用 H.264/CRF 35 编码。
2. 该投影版本成为 manifest 的必填冻结字段；预检、并发校准和完整实验必须使用同一
   编码参数。任一其它投影版本在真实调用前失败。
3. Seed 联系表、完整 ASR、融合、金标、60 秒分块和 10 秒重叠保持不变。金标仍不得
   进入模型提示或后处理；Qwen 仍不使用 Provider 原生 Schema，只做一次本地校验。
4. 这不是生产 API 的媒体策略，也不绕过 ADR-0013 的 48 小时 TTL 审计。目标服务器
   必须复跑同一协议；质量门槛未满足前，不宣布 Qwen 胜出。

## 后果

- Qwen 临时上传不再由无必要的高码率源块主导，本机验证可以进入 60 秒预检门。
- 低分辨率或低帧率可能损失细节，因此只能由已冻结的 7/19 分钟质量评分决定是否保留
  Qwen 候选路线。
- 既有失败的 lifecycle journal 继续保留；新的成功上传仍须等待提供方 TTL 与安全余量
  后才可通过研究审计。
- `v1` 曾因预检误取通用 MPEG-4 路径而未真正贯彻该投影；该失败账本保留不改写。
  `v2` 修复接线后暴露出横屏 160×120 合成媒体不满足 Qwen 的输入约束；`v3` 将规则
  收紧为最短边 160 像素，并以真实 2 秒合成探针验证通过。
