# 0015：长视频融合采用显式分块相对时钟

状态：已接受（2026-07-22）

## 背景

长视频研究最初要求 Seed 融合模型在每个 60 秒块中输出原视频的绝对时间。真实 19 分钟运行显示，后续分块中的视觉和语音证据虽然有效，融合输出仍会回到该块的本地时间轴。旧版把这类输出一律作为无效时间而拒绝，导致已完成的视觉与 ASR 证据无法形成候选。

不能依据数字大小猜测模型使用的是绝对时间还是相对时间；这种猜测会在块边界处制造不可审计的时间偏移。

## 决策

1. 研究协议 `long-video-ab-v3` 向融合 Skill 只提供当前块的相对语音、视觉证据，并明确要求输出范围为 `0..chunk_duration_seconds` 的相对时间。
2. 本地代码先验证相对时间合同，再以确定性方式加上该块的源视频起点，得到公开候选使用的绝对时间。
3. 超出分块范围的输出以 `fusion_relative_candidate_time_invalid` 失败；不得采用数字量级、文本猜测或二次模型调用修复时钟。
4. v2 与 v3 的融合输入/输出合同不同。v2 的完整运行不得与 v3 结果合并评分；任何路线都必须在相同版本下重新通过预检、校准和三次正式运行。

## 后果

- 真实 19 分钟 Seed 纵切片已在 v3 下完成一次全覆盖本地运行，清理正常、总耗时约 265 秒。这只验证时钟合同与端到端可执行性，不构成质量胜出、统计结论或生产 SLA。
- 该决策不改变 60 秒分块、10 秒重叠、金标隔离、无重量字段和用户确认边界。
- Qwen 路线仍须独立通过其上传、Schema、清理和质量门禁，不能借用 Seed 的成功结果。
