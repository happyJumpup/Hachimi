# 0010：训练数据留在同设备且仅有一个未完成场次

## 状态

已接受，2026-07-21。

## 背景

竞赛版需要让用户保存草稿和方案、恢复训练、查看记录并生成海报，但三天交付不建设账号、服务端数据库或跨设备同步。训练场次又包含活动计时、休息截止时间和实际完成量；如果同一设备同时创建多个未完成场次，恢复入口、记录归属和计时都会变得含糊。

## 决策

- 训练档案、方案草稿、方案库、未完成训练、训练记录和 Pet 可见性均保存在浏览器 IndexedDB 的 Dexie v2 数据库中。
- 同一数据库固定只有一个 `sessions/current`。开始新训练使用原子 `add`，已有未完成训练时只允许继续或明确提前结束，不能覆盖。
- 场次保存不可变方案快照和实际执行进度；完整完成或提前结束时，以单一事务写入 ID 等于 `sessionId` 的训练记录并删除当前场次。
- 未完成训练不进入记录、不生成最终卡路里或海报；活动时间只按前台计时，休息按计划时长封顶。
- 所有场次命令使用 revision 做乐观并发检查；重复点击、刷新重放和多标签页冲突不得静默推进两次。
- 用户可以在“我的训练”中明确清除全部同设备训练数据。

## 影响

- 浏览器清除站点数据、无痕模式或 IndexedDB 不可用会使训练数据不可恢复，界面必须明确提示，不能声称已云端保存。
- 更换设备不会同步档案、方案或记录；这属于首版已接受的限制。
- 后端部署或重启不影响已经写入 IndexedDB 的训练数据。
- 未来接入账号同步时，应替换 Repository 并设计冲突协议，不能在现有表上悄悄增加后台同步；该变化需要新的 ADR 和数据迁移。
