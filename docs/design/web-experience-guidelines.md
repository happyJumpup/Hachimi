# 本地视频训练原型 Web 体验设计规范

Status: frozen product contract; implementation acceptance pending

Updated: 2026-07-21

Applies to: 本地视频导入与分析、方案编辑、我的训练、训练中、休息／暂停、完成结果

## 1. 体验原则

1. **训练任务优先。** 每个界面只有一个醒目的下一步，Pet、指标和装饰不得抢占训练控制。
2. **真实反馈。** 清楚区分完整结果、部分结果、空结果、系统失败、容量繁忙和快速体验方案；只展示真实处理时间线，不用动画、预计时间或伪进度掩盖未知状态。
3. **单手可操作。** 390×844 下主操作固定在拇指易触区域，关键控件不依赖悬停或细小图标。
4. **保留控制权。** 用户主动确认候选、本组完成、继续训练、跳过和结束；系统不自动开始下一组。
5. **轻量陪伴。** 哈肌咪持续可见但不遮挡视频、计时和按钮；隐藏或加载失败不影响训练。

## 2. 画布与响应式

### 2.1 手机主画布

- 主要验收视口为 390×844 CSS px，同时支持最小宽度 320px。
- 页面使用 `100dvh`，顶部和底部内边距必须包含 `env(safe-area-inset-*)`。
- 内容左右安全边距为 16px；同组元素间距从 4、8、12、16、24、32px 中选择。
- 训练和视频界面的首要按钮应在不滚动或最少滚动情况下可见。
- 底部固定操作区必须为内容预留空间，不能覆盖表单、最后一条动作或系统手势区域。

### 2.2 桌面竖屏舞台

- `min-width: 900px` 时，页面背景铺满窗口，核心体验居中于宽 430px、近似 9:16 的竖屏舞台。
- 视频候选面板可以在舞台右侧展开，但视频、时间与主操作仍保持在竖屏舞台中。
- 方案和“我的训练”的可读内容宽度不超过 880px；训练界面仍保持手机宽度，不拉伸控制距离。
- 桌面只增加留白和辅助信息，不出现仅桌面可用的关键操作。

## 3. 视觉语言

### 3.1 颜色 token

沿用当前代码中的 token，不在本切片引入第二套主题：

| Token | 值 | 用途 |
| --- | --- | --- |
| `--bg` | `#07090b` | 页面底色 |
| `--surface` | `#101417` | 卡片、底部操作区 |
| `--surface-raised` | `#171c20` | 输入框、选中前控件 |
| `--ink` | `#f3f5f2` | 主文字和关键数值 |
| `--muted` | `#879197` | 次级说明和元信息 |
| `--line` | `rgb(255 255 255 / 9%)` | 默认分隔与边框 |
| `--line-strong` | `rgb(255 255 255 / 17%)` | 浮层和强调边框 |
| `--cyan` | `#26ebd5` | 主操作、焦点、进行中和成功 |
| `--coral` | `#ff6f61` | 危险、警告、序号和局部强调 |

- 电青色代表“可以继续”或“正在进行”，不能同时承担错误含义。
- 珊瑚色只用于危险操作、失败提示或少量视觉节奏，不铺满大面积背景。
- 正文与背景需达到 WCAG AA 对比度；小号灰字只用于非关键说明。
- 不使用抖音商标、品牌渐变或复制旧 GPL 界面的视觉组件。

### 3.2 字体与层级

- 中文字体栈：`PingFang SC, Microsoft YaHei UI, Noto Sans CJK SC, sans-serif`。
- 展示数字和英文标签可使用现有 `Barlow Condensed`，加载失败时使用 `sans-serif`。
- 页面标题 32–40px／700，动作名称 24–28px／700，关键计时 48–72px／700，正文 14–16px，辅助文字不小于 11px。
- 英文眉题只作装饰提示，不能承载中文界面没有的信息。
- 数字使用等宽数字特性，倒计时变化时不引起布局跳动。

### 3.3 形状与层次

- 页面卡片圆角 16–18px，舞台和大浮层 24px，输入框和次级按钮 10–12px，胶囊标签使用全圆角。
- 阴影只用于浮层、主按钮和桌面舞台；边框负责大部分层级区分。
- 训练控制区优先使用稳定矩形，不让装饰性切角降低触控面积。

## 4. 输入、触控与可访问性

- 所有可点击控件的实际触控区域至少 44×44px；相邻危险与主操作之间至少留 8px。
- 图标按钮必须有中文 `aria-label`；图标不能是唯一的状态表达。
- 键盘焦点使用 2px 电青色外框及 3px 外偏移，不移除 `focus-visible`。
- 表单必须有可见标签；校验错误紧邻字段显示，并保留用户已填写内容。
- 动态阶段、倒计时结束、保存完成和错误结果使用适度的 `aria-live`，秒级倒计时不每秒播报。
- 视频需要 `playsinline` 和系统播放控件；关键训练操作不得依赖自动播放成功。
- 颜色之外同时使用文字、图标或形状表达成功、警告和失败。

## 5. 全局导航与组件

### 5.1 导航

- 顶部使用轻量品牌锁定和当前页面标题；主页面入口使用“找动作”“方案草稿”“我的训练”。
- 非训练页存在未完成训练时，在底部操作区上方显示一条“继续训练”召回条，不能覆盖当前页面主按钮。
- 训练页不显示常驻底部导航，避免误触离开；离开使用明确的返回或暂停操作。

### 5.2 按钮

- 每个视口最多一个电青色实心主按钮。
- 次级按钮使用描边或透明背景；危险按钮使用珊瑚色文字，确认弹层中才可使用珊瑚色实心按钮。
- 禁用态保留可读文案，降低对比度并禁止阴影；加载态保持按钮宽度稳定。
- 主按钮文案使用明确动作：“分析视频动作”“加入草稿”“开始训练”“完成本组”“准备继续”“分享海报”。

### 5.3 状态组件

| 状态 | 视觉 | 文案与操作 |
| --- | --- | --- |
| 加载 | 静态骨架或低频呼吸，不改变布局 | 真实阶段＋已处理时长＋暂时发现的动作线索数；“离开后仍可回来查看”＋“取消” |
| 恢复中 | 中性状态条，不重新播放入场动画 | “正在恢复这次分析”＋最后已知处理位置 |
| 空 | 单一图形／序号、标题、短说明 | 提供一个主操作和至多一个次操作 |
| 失败 | 珊瑚色边框或状态点，不使用整屏红色 | “这次没有分析成功”＋“重试” |
| 部分结果 | 珊瑚色缺口段叠加在来源时间线上 | 可靠候选可使用；每个缺口显示绝对范围和“重试这段” |
| 繁忙 | 中性浮层和人数提示 | “稍后再试”＋“使用快速体验方案” |
| 成功 | 电青色状态点和结果内容 | 直接进入下一步，不额外弹庆祝框 |
| 自动保存 | 小型状态点和“视频与方案已保存到本机” | Blob 写入失败时明确“视频仅本次打开可用” |

## 6. 六个核心界面

### 6.1 视频与动作分析 `/`

```text
┌ 品牌                         方案草稿 2 ┐
│ [ 选择本地视频 ]                         │
│ 已选：手臂训练.mp4 · 00:54 · 已保存到本机 │
│                                         │
│              9:16 视频                  │
│          当前时间 / 视频时长             │
│                                         │
│          [ 分析视频动作 ]                │
└─────────────────────────────────────────┘
  当前环境支持：最长 60 秒 · 最大值来自服务端
  [快速体验：使用团队示例视频]
```

- “选择本地视频”是首要入口；受控视频折叠为固定标注的快速体验，不能与本地文件并列成两个同权主按钮。
- 选片后展示文件名、时长、本机保存状态和由 `GET /api/v1/capabilities` 返回的实际秒数／字节上限。超过限制时先说明限制，再给“重新选择”“使用快速体验”和“创建动作”。不写死“支持 10 分钟”。
- 本地媒体保存失败时仍可在当前标签页预览，但状态必须改为“视频仅本次打开可用”；刷新恢复不可用时不能继续显示已保存。
- 分析中使用覆盖舞台的半透明层，显示真实阶段、“已处理 00:42 / 01:00”和“暂时发现 3 条动作线索”。运行中的线索数不是融合候选数；中间线索只读，不提供勾选、编辑或加入方案。
- 分析层提供“返回其他页面”和“取消分析”两个不同操作。返回或页面刷新不发送取消，并提示用户稍后可回来查看；只有显式取消或确认更换来源才结束运行。
- 恢复页面先显示最后快照和“正在恢复这次分析”，再连接新事件；不把恢复渲染成第二次分析，也不重置已处理时长。
- 终态候选在手机使用可滚动底部面板，桌面可放在视频右侧；动作按绝对时间排列，将 `follow_along`／`teaching_demo` 映射为“跟练执行”／“教学演示”。`unknown` 显示“类型需确认”，且影响参数时集中提出一次确认。
- 来源时间线用电青色表示已覆盖，用珊瑚描边表示覆盖缺口。每个缺口卡显示 `03:00–04:00 未完成分析` 和“重试这段”；重试期间只锁定该缺口，不隐藏两侧可靠候选，失败后按钮仍保留。
- 完整覆盖但无动作、系统失败、部分结果、容量繁忙、本地上传关闭和媒体丢失分别使用独立文案，不能共用一个错误组件或回填预置候选。

### 6.2 方案编辑 `/plan`

```text
← 继续找动作                 已自动保存到本机
训练方案草稿                       3 动作 / 9 组
[01 动作卡：来源、模式、参数、操作]
[02 动作卡：来源、模式、参数、操作]
[＋ 创建动作]
──────────────────────────────────────────
[另存为]                     [开始训练]
```

- 动作卡按执行顺序显示大号序号；视频动作显示来源和演示片段，自建动作显示“无参考视频”。
- 来源循环按真实执行顺序展开，例如 `A1 → B1 → A2 → B2`。每次出现有独立序号与卡片；轮次可用小标签辅助理解，但不折叠成可展开的嵌套循环，也不把轮次写进组数。
- 上下移动、复制和删除保持可见；字段较多时分组为“训练目标”和“休息与重量”，不压缩成难点按的小网格。
- 固定底部操作区包含描边“另存为”和主按钮“开始训练”。
- 空态使用“继续找动作”“创建动作”“使用快速体验方案”，快速体验入口必须带固定标签。
- 开始训练前的结构错误在对应动作卡定位，不用只有顶部 toast 的错误提示。

### 6.3 我的训练 `/mine`

```text
我的训练
[继续训练：当前动作 / 进度]       ← 有时才显示
[方案草稿：动作数 / 更新时间]
已存方案
[方案卡] [方案卡]
训练记录
[状态 · 日期 · 时长 · 约千卡]
```

- 未完成训练卡始终排第一并使用电青色左边线；不能与已存方案混在一起。
- 草稿只显示一张；方案卡提供“开始训练”和溢出菜单，避免整卡堆叠多个按钮。
- 记录用“已完成”或“提前结束”文字标签，不能只靠颜色区分。
- 所有分区均为空时，主操作是“去找动作”，快速体验方案作为次操作。
- “清除本机训练数据”放在页面末尾的低强调设置区，并需要二次确认。

### 6.4 训练中 `/training`

```text
动作 1 / 3                       暂停 · ⋯
┌───────────────────────────────────────┐
│ 视频演示片段循环 / 自建动作无视频状态 │
│                               哈肌咪  │
└───────────────────────────────────────┘
拖拽弯举
第 2 / 3 组                 每组 10 次
────────────────────────────────────────
                 [完成本组]
```

- 动作名称、当前组／总组和目标必须在同一视口可见；重量为空时不显示占位数值。
- 视频片段在定义的绝对时间范围内循环；原视频不可播放时保留动作和训练控制。
- 本地媒体存在时从 IndexedDB Blob 恢复并播放原片段。媒体丢失时显示“需要重新选择原视频”和文件基本信息；重新选择是次级操作，不能阻断完成本组、暂停或结束训练。
- 时长型主区域改为稳定的大号倒计时，主按钮先显示“开始计时”，计时中显示“暂停”。
- 次要操作放在“更多”面板：跳过剩余组、隐藏／显示哈肌咪、提前结束训练。
- Pet 固定在视频／展示区右下方，不越过底部控制区，任何状态下都不能覆盖字幕、计时或按钮。

### 6.5 休息／暂停 `/training`

```text
休息中
                         00:42
下一组：拖拽弯举 · 第 3 / 3 组
                  哈肌咪（休息）
[返回视频]                         [结束休息]
```

- 休息倒计时是最大视觉信息，下一组内容紧随其后；“结束休息”是描边按钮，避免误触。
- 倒计时结束后标题变为“可以继续了”，主按钮变为“准备继续”，不会自动跳回活动训练。
- 主动暂停显示“训练已暂停”和“继续训练”；恢复后的动作进度保持不变。
- 从非训练页召回时显示同一休息截止时间或暂停状态，不能重新开始倒计时。

### 6.6 完成结果与海报 `/result/:recordId`

```text
训练完成
┌───────────────────────────────────────┐
│ 方案名称                              │
│ 24 分钟       约 126 千卡             │
│ 完成 3 个动作              哈肌咪完成 │
└───────────────────────────────────────┘
[分享海报]                  [下载海报]
再练一次 · 查看记录 · 继续找动作
```

- 屏幕结果卡与导出海报使用同一信息层级，但导出固定为 1080×1920 PNG。
- 海报只包含方案名称、训练时长、约消耗卡路里、完成动作数和哈肌咪，不包含档案与视频。
- 分享失败后保留结果页并显示下载操作，不用错误页替换训练结果。
- 提前结束使用“本次训练已结束”的中性标题和实际完成摘要，不出现庆祝动效和“完成海报”。

## 7. Pet 规范

哈肌咪是训练呈现层，不拥有任何训练控制逻辑。素材加载失败时隐藏容器并保留等价状态文字，训练继续进行。

下一轮原型不新增 Pet 状态、对话、动作示范或控制能力；正式产品名也不由 Pet 名称代替。本节现有五态合同保持不变。

| 训练状态 | Pet 状态 | 表现要求 |
| --- | --- | --- |
| 尚未开始／组间准备（`paused/before_start`、`paused/between_actions`） | 待机 | 低频呼吸或轻摆 |
| 动作训练进行中 | 训练 | 节奏略快，不示范动作 |
| 休息倒计时 | 休息 | 坐下／放松式短循环 |
| 主动暂停／页面隐藏／刷新恢复／准备继续 | 暂停 | 静止或极低频动作 |
| 完整训练结束 | 完成 | 一次短庆祝后停在完成姿态 |

- 使用五张透明 WebP 或等价的五状态资产，总体积不超过 1MB。
- 展示宽度在 390px 视口下建议为 88–112px；依据素材留白调整，但触控控件与 Pet 至少间隔 8px。
- 默认显示；“隐藏哈肌咪”位于训练更多菜单，隐藏后同位置不保留空白。
- 隐藏是同设备长期偏好；恢复入口必须始终可在训练更多菜单找到。
- `prefers-reduced-motion: reduce` 下不循环位移、缩放或闪烁，只切换静态状态帧。

## 8. 动效与性能

- 页面过渡 180–220ms；按钮反馈 120–160ms；不使用超过 400ms 的阻塞式转场。
- 分析扫描和 Pet 循环只改变 `transform` 与 `opacity`，避免影响布局；后台页面停止非必要动画，但不能因此取消服务端分析。
- 本地视频对象 URL 在切换来源或组件释放时撤销；大型 Blob 不复制到响应式状态或 Canvas，导入与上传状态不能阻塞训练页的基础控制。
- 休息倒计时、训练计时和保存状态由真实数据驱动，动画不能成为计时来源。
- `prefers-reduced-motion: reduce` 下关闭页面位移、扫描线、脉冲和 Pet 循环，保留即时状态切换。
- 图片和 Pet 加载需要固定尺寸，失败时不引起控制区跳动；训练关键路径不能等待 Pet。

## 9. 中文文案

- 使用用户正在执行的自然动作：“继续找动作”“返回视频”“创建动作”“完成本组”“准备继续”“继续训练”。
- 不使用“返回信息流”；Web 竞赛版也不假装用户正在抖音推荐页中。
- 不把方案称为“视频合集”，不把动作分析称为“AI 私教”或“一键生成方案”。
- 不公开“ASR”“VLM”“Fusion”“Provider”“置信度”等工程词；使用“理解语音”“定位动作”“整理候选”。
- 进度使用“已处理 00:42 / 01:00”“暂时发现 3 条动作线索”；覆盖缺口使用“03:00–04:00 未完成分析”。不使用“模型卡住”“部分帧失败”等内部归因。
- 卡路里只写“约 N 千卡”，档案不完整时可补充“通用约值”，不显示区间或精确承诺。
- 错误文案先说明发生了什么，再给可执行动作；不要求用户理解错误码。

## 10. 设计验收清单

- 390×844 下六个核心界面的主任务无需横向滚动，底部系统手势不遮挡按钮。
- 所有关键按钮触控区域至少 44×44px，键盘焦点清晰，表单拥有可见标签。
- 桌面端保持竖屏训练舞台，关键操作与手机一致。
- 本地导入是首要入口，受控视频明确标注为快速体验；实际格式、字节和秒数限制来自能力接口且可见。
- 页面切换、刷新和 SSE 断线后恢复同一分析；只有显式取消或确认换源才终止。
- 真实进度、中间只读动作线索、完整结果、部分结果、空结果、失败和繁忙具有可辨别的标题、说明和后续操作。
- 每个覆盖缺口显示绝对时间和独立重试入口；重试失败不隐藏可靠候选或移除按钮。
- 跟练执行与教学演示在参数语义上可区分；循环内容在方案中按真实顺序展开，没有嵌套循环控件。
- 训练中动作、组数、目标和主按钮同屏；休息结束后只进入“准备继续”。
- Pet 五状态正确、可隐藏且不阻塞；低动效模式为静态状态帧。
- 完整训练海报字段无多余训练明细；提前结束不生成完成海报。
- 全站不出现“返回信息流”、模型日志、数值置信度、供应商名称或伪造进度。
