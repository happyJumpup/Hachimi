## 结论

DeepSeek 不进入当前竞赛生产路线。当前 GYMTI 由 [ADR-0044](../adr/0044-gymti-uses-ark-doubao-minimal-data-and-independent-concurrency.md) 固定为 Ark／豆包最小数据调用和独立三并发降级；`questionaire/` 的 DeepSeek 代码仅是被排除出构建的参考原型。

参考原型证明了“LLM 可参与选题和结果叙事、失败时可本地降级”的交互想法，但其调用面不满足正式产品的最小数据合同：原型选题会组合答题明细、排名和候选展示内容，结果叙事还会组合完整答题明细、置信信息和档案上下文；异常路径可能把供应商错误正文带入本地日志或 API 错误。正式实现已经收窄为稳定 ID、服务端派生信号和结构化正式结果，不应倒退到原型载荷。

## Issue #5 建议验收项

- 明确 DeepSeek 目标产品、模型、区域、训练复用、内容留存、日志与删除能力，并由发布人保存不含账号标识的确认回执；无法确认则不得构造生产客户端。
- 只允许复用 ADR-0044 的选题／叙事白名单载荷；禁止发送展示文案、训练档案、身份、训练历史、自由文本画像、完整回答、提示词或模型原文到日志和回执。
- 使用测试合成稳定 ID 验证合法选题、非法输出、超时、429、5xx、重试耗尽和本地降级；测试报告只保留聚合计数、耗时和错误类别。
- 在同一匿名测试契约下比较 Ark／豆包与 DeepSeek 的结构合规率、有效选题率、叙事校验通过率、P50／P95、单次成本和降级率；没有足够样本时记录 `insufficient_evidence`，不宣布胜者。
- 若 DeepSeek 成为候选，必须通过独立三并发／第四条立即降级、无问卷内容日志、无分析额度耦合、目标 CloudBase 候选 smoke 和回滚门槛，再另立 Provider 切换 ADR。
