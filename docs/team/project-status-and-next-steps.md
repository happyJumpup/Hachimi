# 哈基米练臂力动：项目进展与下一步

> 团队结论：当前原型可以进入第一版产品（MVP）开发，但还不适合直接对外发布。

## 1. 我们在做什么

哈基米练臂力动面向已有训练意图、主动寻找健身视频的用户。它把视频里的动作变成可确认、可组合的训练内容，并记录原视频起止位置、组数、次数或时长、休息时间。产品里的陪练角色名为“哈肌咪”。

产品的核心不是收藏完整视频，而是沉淀可训练、能找回原视频的动作。AI 通过语音和画面提出候选，最终由用户决定。手工新增的动作也可以加入方案，但没有原视频入口。

## 2. 当前版本已经完成什么

首个可运行版本已经打通“从视频找到动作，再加入方案草稿”这一段流程：

- 用户在我们预先配置的演示视频中，选择当前播放位置并点击“添加动作”。
- 系统结合附近的语音和画面识别动作，并以列表形式给出候选。
- 用户可以预览、修改名称和时间、多选需要的动作。
- 动作可以来自不同视频，也可以手工新增；加入草稿后，可以继续编辑组数、次数或时长、休息时间，并进行排序、复制和删除。
- 当前只有一个自动保存在本机的方案草稿，刷新页面后仍能恢复；“另存为”尚未实现。

一条真实演示视频已经跑通 AI 识别，使用后的临时文件也能清理。正式训练、卡路里估算、哈肌咪陪练、方案另存为、完成海报和分享仍未实现。

## 3. 为什么可以继续开发，但还不能发布

“识别动作并加入草稿”已在受控样例中运行，说明核心方案初步可行，可以继续开发。但它还不能稳定处理各种视频，也没有证明目标用户一定喜欢，仍需更多样例和真实体验反馈。

但它还不是一个可以交给普通用户完整使用的产品。目前只验证过一条真实演示视频；最近一次分析约需一分钟，这只是单次观测，不代表稳定速度。原型只支持我们预先配置的视频，并运行在网页中，还没有接入抖音小程序。更重要的是，用户现在只能整理方案，还不能真正跟随方案完成一次训练。

进入对外测试前，至少要满足五项条件：用户能完成一次训练、不同类型视频的识别表现基本稳定、等待时间达到团队可接受水平、抖音小程序中的核心流程跑通，并补齐健身安全提示和视频隐私说明。

## 4. 下一阶段怎么推进

下一阶段的共同目标是：**让用户按照方案草稿真正完成一次训练。**

- **产品工作流**：收敛最小训练流程，包括动作顺序、组数/次数或计时、组间休息、中断恢复和完成状态；继续保持轻量，不扩展成完整健身 App。
- **技术工作流**：实现训练过程；并行补充不同类型视频的识别测试，记录稳定性和耗时，逐步缩短等待；网页流程稳定后再适配抖音小程序。
- **设计工作流**：完善手机端训练、休息和完成页面；为后续陪练功能优化角色“哈肌咪”的现有形象，并允许用户隐藏该角色。

用户可以完成一次训练后，再叠加卡路里估算值、方案另存为、完成海报和分享等能力。

## 5. 当前风险与详细资料

当前需要团队共同关注五件事：识别效果能否覆盖更多健身视频、等待时间是否可接受、训练流程是否足够简单、抖音小程序有哪些限制，以及动作建议和视频内容分析如何做好安全提示与隐私说明。
