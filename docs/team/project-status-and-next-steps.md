# 哈基米练臂力动：项目进展与下一步

> 更新于 2026-07-21。团队结论：竞赛版 Web MVP 的代码闭环已经完成并可进入发布验收；公网体验仍取决于正式媒体、腾讯云环境和真机验收，不能把本地通过表述为已经上线。

## 1. 我们在做什么

哈基米练臂力动面向已有训练意图、主动寻找健身视频的用户。它把视频里的动作变成可确认、可组合、可执行的训练内容，并保留原视频入口和动作时间段。AI 通过语音和画面提出候选，最终由用户决定；自建动作可以没有参考视频。

## 2. 当前竞赛版已经完成什么

当前 Web MVP 已串起本机完整闭环：

- 用户点击后对不超过 60 秒的受控视频发起整段真实 ASR 与视觉并行分析，校正、多选候选并跨视频加入草稿；播放和拖动不会自动触发。
- 草稿自动保存，支持排序、复制、删除、参数编辑和无视频自建动作；已存方案支持“另存为”。
- 次数型与时长型训练、组间休息、暂停、离页和刷新恢复、跳过剩余组、提前结束均已实现。
- 同设备同时最多存在一个未完成训练；完成或提前结束时按实际执行量生成训练记录。
- 训练档案只保存在本机，用于显示“约 N 千卡”；哈肌咪包含待机、训练、休息、暂停、完成五态，可隐藏且加载失败不阻断训练。
- 完整训练可以生成 1080×1920 PNG 海报，并使用 Web Share API 或下载兜底；提前结束不生成完成海报。
- 普通访客可使用明确标注、不会冒充 AI 结果的快速体验方案；评委体验码提供真实分析的独立访问级别。
- 单一 54.87 秒旧视频已连续三次通过 Ark 与豆包流式语音识别 2.0 真实联调，观测为 10.96–13.41 秒/视频分钟；临时材料、部分成功警告和清理已验证。

自动化基线覆盖 Web 单元、API、移动视口 E2E、构建、OpenAPI、镜像逐层审计和容器健康检查。具体数量和 smoke 观测只记录在对应提交、CI 与发布记录中，避免把一次结果写成长期保证。

## 3. 为什么代码可发布验收，但还不能宣称已经上线

当前缺口不再是训练产品功能，而是生产发布输入和外部验收：

- 需要 2–3 条团队授权且每条不超过 60 秒的正式演示视频、来源清单、COS/CDN 地址和服务器只读媒体缓存。
- 需要腾讯云服务器、域名、DNS、SSH，以及通过校验的生产 FFmpeg 路径与两个 SHA-256 配置值。
- 需要在目标服务器完成部署、三路真实 AI 并发、重启、上一镜像回滚和恢复当前镜像。
- 需要 Android Chrome 与 iOS Safari 真机验证视频、IndexedDB、SSE、分享和安全区。
- 武汉站的截止时间、体验链接、PPT、录屏和演示时长仍应从赛事飞书群取得书面确认。

现有真实识别只覆盖一个受控样本，不能代表复杂视频分布；性能记录也是观测值，不是稳定延迟承诺。抖音小程序、待练收集、用户上传视频或 Pet、账号和跨设备同步不在本次三天版范围内。

## 4. 下一阶段怎么推进

下一阶段只做竞赛发布收口，不继续扩产品范围：

1. 登记并同步正式演示媒体，完成每条视频的人工标注触发点和真实云 smoke。
2. 在目标腾讯云环境验证容量；达不到 4C/8GB 与三路并发门槛时，按 Runbook 降级槽位，不使用 Mock。
3. 完成双端真机验收、五分钟演示脚本、录屏备份和已知限制清单。
4. 以不可变镜像 SHA 部署，执行重启与回滚演练后再对外宣布公网链接。
