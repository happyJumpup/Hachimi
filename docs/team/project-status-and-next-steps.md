# TrainPal：项目状态与下一步

> 更新于 2026-07-23。五分钟后端、TrainPal Vue design v1、七猫动效与 GYMTI v1 已形成本地候选；Provider 候选 `d742268` 因真实 Qwen/COS、五分钟质量、Canary 与回滚证据不足而延期。旧 CloudBase A/B、三路评委并发与 B→A→B 回滚记录继续作为历史证据；当前“五条受控来源、无冷却公开单并发、GYMTI Ark／豆包独立三并发”候选尚未取得线上通过回执，`009`／`011` 均不得称为当前最终版。

## 1. 当前产品方向

TrainPal 是独立 Web、用户可见的唯一 Agent 和小猫教练的统一身份。当前主路径是：

`本地视频导入 → 显式内容理解 → 基础方案提案 → 用户编辑／可选个性化 → 训练执行 → 结果与陪伴成长`

- 本地视频是主入口；受控视频是明确标注的快速体验兜底。
- “刷到就是练到”是把用户已保存或拥有的视频变成可执行训练的价值主张，不代表当前已有平台内一键入口。
- 原视频与训练数据留在当前浏览器设备；服务端只接收单次分析临时副本并在所有终态清理。
- 页面切换、刷新和 SSE 短暂断线不取消分析；用户返回后凭 `run_id` 恢复真实状态。
- 过程展示真实已处理时长与暂时候选数。可靠部分结果保留覆盖缺口和逐段重试，不能冒充完整分析或无动作。
- Agent 保留来源证据与不确定标记，循环内容按真实顺序展开为扁平动作安排，不把内部教学／跟练判断暴露为公共字段。
- 页面按首页、分析、方案、个性化、训练中心、训练中、结果和“我的”拆分；一个页面只承担一个主要任务。
- 规划与结果使用温暖明亮的训练手账视觉，训练中切换到高对比深色舞台；移动端完整可用，桌面端不渲染固定手机外壳。

## 2. 已冻结的产品与 Agent 合同

用户只看到 TrainPal。内部链路为：

`内容理解 Provider → 训练编译 Skill → 基础方案 → 动作要点补充 Skill／可选个性化调整 Skill → 确定性训练引擎`

- Dexie 保存本地视频 Blob 与稳定 `local:<UUID>`，方案和训练引用同一来源；媒体丢失时支持重新选择并校验。
- `GET /api/v1/capabilities` 公开当前上传开关、分析秒数上限和字节上限。
- `POST /api/v1/analysis-runs/local` 以 multipart 创建完整分析或绝对区间重试，沿用现有运行查询、SSE 与取消接口。
- `AnalysisRunView` 提供来源时长、已处理时长、暂时候选数、`complete | partial | insufficient` 覆盖状态和覆盖缺口；公开候选不再包含 `segment_role`，用户通过确认、编辑或删除校正结果。
- Web 在离页／刷新后恢复同一运行，中间结果只读；覆盖缺口逐项重传本机 Blob，按绝对时间合并可靠结果。

当前竞赛后端已把能力合同和分块实现收敛为完整源文件不超过 5 分钟：一次 ASR、60 秒视觉块、10 秒重叠、单块 20 秒和整次 180 秒。历史 CloudBase 候选曾用 67.83 秒和 295 秒授权样本通过私有真实链路，并完成当时的三路评委并发、第四路 `429`、临时材料清理与 B→A→B 回滚；公网三条结果均为 `partial`。当前候选改为无冷却公开单并发，必须重新验收并证明同会话终态清理后立即重入，不能沿用旧并发回执或宣称任意视频生产级解析。

- 训练编译 Skill 必须先输出可立即使用的整份基础方案；不再把独立候选收件箱作为主流程。
- 动作要点补充按已确认动作非阻塞运行；可使用带引用的网页结果，失败时可明确标注模型通用建议，训练中不联网。
- 个性化调整只在用户主动选择“让 TrainPal 调整这次训练”时运行，不阻塞基础方案，也不自动应用。
- 三个 Skill 不互相调用、不接收原始媒体、不写草稿、不读取训练状态机，并以任务 ID、合同／Skill 版本和输入指纹保证幂等与迟到结果拒绝。
- 训练参数来源统一为 `video | rule | personalized | user`。用户值高于一切，重量只允许用户填写。
- GYMTI v1 使用共享版本化合同、5–8 题确定性计分、七猫单一推荐和用户明确确认；进行中／待展示／当前结果只保存在 Dexie v5。GYMTI、训练经验、已确认教练风格、可选个人信息和带场景轻反馈组成个性化上下文，但不是跨视频数值默认值。
- 年龄、性别、身高和体重主要用于卡路里约值，只能作个性策略弱参考，不得推断人格、健康状态或直接决定训练强度。
- 来源片段默认只作参考；只有可靠来源节奏才展开为 `A1 → B1 → A2 → B2` 这类扁平执行时间线。公开方案不再要求用户判断片段用途。
- 训练引擎继续确定性负责计时、休息、准备继续、恢复、实际完成量、记录和海报；训练中 Agent 不接管状态机。

## 3. 当前工程真实状态

### 已有基线

- Vue 3 + TypeScript Web、FastAPI 分析服务和 pnpm workspace 已建立。
- 本地视频导入、受控来源、Analysis Run、SSE、访问分级与能力接口已有工程基线。
- Dexie v5 已有本地媒体、单一当前草稿、方案、单一未完成训练、记录、档案、偏好，以及 GYMTI 三个单槽生命周期基线。
- 次数／时长训练、休息墙钟、刷新恢复、提前结束、卡路里约值、结果与分享已有基线。
- 当前 production 配置使用真实 `cloud` Provider；Ark、豆包流式语音识别 2.0 与确定性媒体／融合路径已经接入，测试 Provider 在非测试环境拒绝启动。
- 移动体验 Brief、TrainPal 身份、个性化、来源节奏、三个 Skill、任务幂等、覆盖状态、移动页面与视觉 ADR 已冻结。
- Vue design v1、七猫动效与 GYMTI v1 已合入五分钟后端；最终候选的 OpenAPI 已从运行时重新生成，公开候选没有 `segment_role`。独立发布审查额外修复了“已有 PUBLIC 稳定版无法安全创建 0% 候选”的 P1：现有访问类型原样保留；路由变更前验证稳定版 100%，变更后验证控制面规则，所有异常路径恢复并验证稳定版 100%／候选 0%。数据面仍必须用 `/health` 的精确提交证明，不能把控制面规则存在当作候选已可访问。
- CloudBase 历史公网版本 `trainpal-demo-009` 曾使用 2 vCPU / 4 GiB、单 worker、最小/最大实例 `1/1`；历史 0% 候选 `trainpal-demo-011` 为 `0/1` 且没有通过数据面身份门禁。当前目标配置为公开分析并发 1、评委分析并发 0，不设置会话／IP 冷却或次数额度；线上状态待新候选回执确认。

Provider 生产化任务已提交候选 `d742268`，但交接结论明确要求不切生产：缺少真实 Qwen 预检／合同验证、目标 COS 生命周期与清理、五分钟 Precision／Recall／F1、稳定 `complete`、版本 C 公网 Canary 和 B→C→B→C 回滚。当前没有可以据此宣布的 Seed／Qwen 质量冠军。

### 不能过度表述的部分

- benchmark 证据可用于排除不满足门禁的组合和指导后续测试，但不能当作生产 Provider 选型结论；
- 下一轮原型保持现有生产 Provider，不因为单次 spike 改路由；
- 当前 Provider 分块基线保持为竞赛运行时；300 秒后端能力已实现且在历史候选验证过，当前新候选仍须重新验证。CloudBase HTTP Access 历史实测请求体上限为 20 MB，Web 继续使用 19 MB 安全上限；
- 后续若切换 Provider，需引用复核后的 benchmark 证据并新增技术路线 ADR，不能只改环境变量后对外宣称升级。
- 已观察到无讲解、音乐配音且画面不写动作名的纯视觉短视频出现动作召回不足和误识别。这证明当前自建内容理解链路可用于原型演示与继续验证，但不能宣称任意健身视频生产级解析。
- `complete | partial | insufficient`、可靠来源节奏、整份基础方案、三个 Skill、`personalized` 来源和个性化提案时效已是新合同，但尚不能按文档存在即视为全链路完成。
- GYMTI v1 题库、七张人格插画和七猫运行资源已经版本化；竞赛目标使用 Ark／豆包最小数据增强和独立非排队三并发，第四条、错误或留存边界未确认时立即使用本地确定性选题与模板叙事。测评不是健康诊断，也不能自动改变训练强度或已确认风格。

## 4. CloudBase 竞赛入口状态

CloudBase Run 是竞赛期间的临时同源 HTTPS 目标，服务合同为 `trainpal-demo`、2 vCPU / 4 GiB、最多一个实例、一个 Uvicorn worker。当前候选允许公开会话无需评委码直接发起真实分析，只有一个共享槽但不设置完成后的会话／IP 冷却；该新合同尚未在线上验证成功。

已完成：

1. 历史版本 A `trainpal-demo-007`（Build `2601400378`）私有 `/health`、`/ready`、签名 FFmpeg、短样本和 295 秒样本；两条均为 `complete`、0 个覆盖缺口。
2. 历史版本 B `trainpal-demo-008`（Build `2601400393`）集成前端后完成私有探针、真实短样本和 `008 → 007 → 008` 实际回滚。
3. 历史公网配置版本 `trainpal-demo-009` 完成当时的 SPA/history、两个独立浏览器上下文、匿名隔离、三路评委 `202`、第四路 `429 + Retry-After` 和三条 SSE 终态。
4. 公网三条运行均完成并诚实返回 `partial`；结束后容量释放。回执只记录服务、版本、Build ID、提交 SHA、资源和环境变量名称，不记录秘密值、环境 ID、域名或真实内容。
5. 历史源码候选 `1da5882` 构建为 `trainpal-demo-011`（Build `2601400511`）；控制面接受路由规则但数据面没有命中候选，事务在上传与模型调用前失败并恢复当时的稳定流量。因此没有公开 `011` 或执行候选回滚；它不是当前最终候选。

仍需完成：

1. 把当前五条已授权来源同步到目标只读媒体基址，验证清单／对象／缓存的条目数、时长和哈希；7/19 分钟原片已不直接进入清单，任何新替换仍须外部裁剪至不超过 5 分钟并压缩到 Web 19 MB 安全上限内。
2. 在 Android Chrome 与 iOS Safari 真机完成选片、上传、前后台、软键盘、安全区和分享验收。
3. 冻结五分钟讲解脚本并录制两份不泄露体验码、Cookie、路径或模型原文的真实闭环视频。
4. 验证 2026-07-24 23:00（Asia/Shanghai）一次性关停任务实际禁用公网映射、把访问收紧为 OA 并把最小实例降为 0。

CloudBase 默认域名首次打开会显示访问确认，需点击“确定访问”；它只适合有限竞赛演示，不是长期生产域名。发布全过程以 [`deploy/cloudbase/foundation-plan.json`](../../deploy/cloudbase/foundation-plan.json)、[CloudBase 操作说明](../../deploy/cloudbase/README.md)和[竞赛 Runbook](../release/competition-runbook.md)为准。

## 5. 发布收口切片

### 已入选：稳定 Provider + Vue/GYMTI

- 保持已验证的 Ark + 豆包 ASR 五分钟分块基线，不接入 Provider 大重构；
- 接入 TrainPal Vue design v1、七猫动画、GYMTI 共享合同、无状态 API、Dexie 恢复与明确风格确认；
- 使用 Ark／豆包最小数据增强与独立三并发／第四路降级；`questionaire/` 的 DeepSeek 路线仅作参考且不进入根工作区测试、源码包或镜像；
- 从运行时重生成 OpenAPI，并统一 320／390／768、低动效、错误恢复和发布镜像门禁。

### 已延期：Provider 与 Skill/Agent 架构扩展

- Provider `d742268` 保留在 #5，补齐真实 Qwen/COS、五分钟质量、清理、Canary 与回滚后再做 ADR-0031 之外的新 Provider 决策；
- `skill-agent-optimization-plan.md` 是赛后 P2 研究输入，不进入本次提交。可保留“Provider 策略层、确定性训练编译、用户触发个性化、非阻塞要点”的方向，但必须先删除旧 `segment_role`、保持本地训练数据边界，并补齐任务 TTL、single-flight、版本指纹、错误脱敏和等价测试；
- 优先把现有前端确定性训练编译提取为纯函数并做前后端等价测试，再判断是否需要新的服务端 Plan API，不在比赛窗口引入新数据库或 SSE 状态机。

### 最终发布结论

- 本地完整测试、Playwright、320／390／768／1440 渲染、源码包／秘密／媒体扫描和双平台镜像审计已经通过；
- 旧精确候选 SHA 曾以 0% `GRAY` 方式构建，但私有数据面身份门禁失败并恢复当时的稳定版本。当前新合同尚未生成可声明成功的 CloudBase 候选或回滚回执；
- PR #9 合并后关闭 #4/#6/#7；#5 继续承接 Provider 与 Skill/Agent 工程，#8 继续承接真机、录屏、最终素材和人工验收。

## 6. 下一次可声明完成的门禁

以下本地工程门已由候选分支通过；Android／iOS 真机仍作为 #8 的人工发布门：

1. `/`、`/analysis`、`/plan`、`/personalize`、`/train`、`/training`、`/result/:recordId`、`/mine` 旅程与路由 Shell 一致。
2. 320、390、768、1440 桌面模拟宽度无主路径阻断；Android Chrome 与 iOS Safari 真机上的视频、软键盘、安全区、固定主操作和分享仍待 #8 人工验收。
3. 方案和训练页使用渐进披露与单一主操作，训练视频按原始比例完整显示。
4. 开发设计画廊不进入生产路由、不连接生产 Provider、不成为运行时 Mock。
5. Vitest、Playwright、可访问性、类型检查、构建和 `git diff --check` 通过。

只有以下证据齐备，才可以把新的“竞赛公网 Demo”候选标为完成：

1. 不可变镜像、配置快照、素材权属、媒体／FFmpeg 哈希和私有 `/ready` 全部通过。
2. 至少一条团队授权本地视频通过真实 Provider 完整 Web 流程，且没有预置候选或测试回退。
3. 一个公开分析成功；占槽期间并发第二条稳定返回带 `capacity` 原因的 429，首条终态清理后同一会话立即再次获得 202，取消后再次清理，无跨会话数据、实例重启或临时材料增长。
4. 默认域名第二浏览器上下文、公网回滚和再前滚已通过；Android／iOS 真机仍须通过。
5. 链接、无需体验码且仅单并发的说明、五分钟脚本、双份录屏、已知限制和关停负责人均已确认。

## 7. 明确暂缓

- 平台分享直达、平台 Cookie／登录态、任意 URL 抓取和信息流抓取；
- 10 分钟生产能力、Provider 切换和大规模并发承诺；
- 服务端训练计划数据库、新 Plan API／SSE 编排和自动执行 Skill 的 Agent 架构扩展；
- 账号、跨设备媒体／档案／方案同步和服务端训练数据库；
- 开放式训练问答、实时姿态判断、自动计数、伤病诊断和个体负重处方；
- 用户上传自定义教练形象、正式 GYMTI 题目之外的自动人格推断。
